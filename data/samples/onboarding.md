# Documentation interne — Arrivée d'un·e nouveau·elle membre

## Processus : Onboarding d'un nouveau membre
Déclencheur: arrivée confirmée d'un·e nouvel·le employé·e
Responsable: manager direct + buddy désigné
Outils: Notion, Google Workspace, Slack
Fréquence: à chaque arrivée
Étapes:
1. Le manager crée les accès (email, Slack, GitHub) une semaine avant l'arrivée
2. Un buddy est désigné pour accompagner la première semaine
3. Jour 1: présentation de l'équipe et tour des outils
4. Semaine 1: lecture de la documentation d'architecture et premier ticket simple
5. Fin du mois 1: point avec le manager sur les objectifs des 3 prochains mois

## Processus : Revue de code
Toute contribution de code passe par une pull request revue par un pair.
Déclencheur: ouverture d'une pull request
Responsable: reviewer désigné
Outils: GitHub
Fréquence: à chaque pull request
Étapes:
1. Vérifier que les tests passent
2. Vérifier la cohérence avec les conventions de code de l'équipe
3. Approuver ou demander des changements
